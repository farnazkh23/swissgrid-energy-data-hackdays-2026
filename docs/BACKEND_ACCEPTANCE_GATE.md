# Backend acceptance gate

`acceptance` reads a persisted artifact bundle without retraining or changing
it. It returns `PASS`, `PASS_WITH_WARNINGS`, or `FAIL`.

The gate requires a complete target contract, point-in-time evidence, resolved
unit/timezone state, completed rolling OOF with holdout isolation, at least one
Champion candidate, valid quantiles and histogram mass, complete provenance,
loadability through the forecast API contract, explicit fallback/abstention
state, and artifact hashes that reproduce the run manifest.

`PASS_WITH_WARNINGS` is permitted for explicit nonfatal diagnostics. A
fallback forecast requires the command's `--allow-fallback` flag; abstention,
missing provenance, corrupted artifacts, missing PIT evidence, histogram
mismatch, and hash mismatch fail closed.

The legacy deterministic mock bundle predates content-addressed run manifests,
so it is useful for API compatibility checks but is expected to fail the final
manifest-hash check until regenerated by a future real-data run.
